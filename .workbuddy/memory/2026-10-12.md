## 10:50 重大发现：QQ 抢键（Ctrl+Alt+B 按下后 QQ 截图同时弹出）

**现象**：木木按 `Ctrl+Alt+B`，QQ 的截图弹出来，他以为微信桥没生效。

内容都是剪贴板里的 `https://github.com/s0md3v/roop`）。

  "**比 RegisterHotKey 更早拿到按键**"的机制，两者互不冲突 → 一边发消息、一边弹截图。
- ⚠️ **重大教训：`RegisterHotKey` 试注册成功 ≠ 这个组合真的没人抢。**

  → 所以 hotkey_scan 的 docstring 已补上这条盲区警告。

**决定性实验（tools/hook_probe.py、tools/hook_probe2.py）**
- v1：自己装 WH_KEYBOARD_LL，命中 Ctrl+Alt+B 时 `return 1` 吞掉。
  木木按键 → 钩子捕获成功（10:50:02）；同时桥的日志里 10:49~10:51 **零条热键记录**
  → 证明**吞掉后 RegisterHotKey 也收不到**，按键被拦死在系统层。
- v2：加了**窗口取证**（捕获瞬间对比顶层窗口快照，找新冒出来的窗口）+ 蜂鸣反馈。

  → **钩子能压住 QQ**，方案可行。

**已实施改动（wx_tray.py）**

## 11:00 真根因锁定：不是 QQ 抢 B，是**桥自己的 Ctrl+C 变成了 Ctrl+Alt+C**

木木反馈两条：① QQ 截图还是弹；② **微信收到的不是他选中的内容**。

**日志铁证**：`wx_bridge.log` 里每一条都是
`准备发送（剪贴板原有内容，30 字）：https://github.com/s0md3v/roop`
→ **选中文字一次都没抓成功**，发的全是剪贴板旧内容（100% 失败率 = 系统性原因，不是偶发）。

**根因（一条链串起两个毛病）**
1. 木木按下 Ctrl+Alt+B 的那一刻，手指**还按着 Ctrl 和 Alt**；
2. 旧代码 `on_hotkey()` 只 `sleep(0.25)` 就开始注入 `Ctrl+C`——0.25s 根本不够人松手；
3. 于是系统收到的是 **Ctrl+Alt+C**：
   - 它不是"复制"→ 选中文字**没进剪贴板** → 桥只能退回旧剪贴板 → **微信收到旧内容**；
   - 而 **Ctrl+Alt+C 正是 QQ 的「长截图」**（见木木的 QQ 快捷键截图）→ **QQ 弹截图**。

**另一条独立线索**：木木在 QQ 快捷键列表里**找不到 Ctrl+Alt+B**——
因为 **B 根本不是 QQ 的快捷键**（QQ 用了 O/F/C/L/T/Z/A/R/E、Ctrl+1/2/F 等，没有 B）。
所以"改 QQ 快捷键"是死路；真正的修法在桥自己身上。

**已实施修复（wx_bridge.py）**
- 新增 `modifiers_down()` / `wait_modifiers_released(timeout=1.2)` / `release_modifiers()`：
  注入 Ctrl+C **之前**先等用户松开 Ctrl/Alt/Shift/Win（轮询 `GetAsyncKeyState`），
  超时则**强制注入 KEYUP** 兜底 —— 保证复制的是干净的 Ctrl+C。
- `grab_selected_text()` 重写：等松开 → 复制 → 若剪贴板没变，**强制松键后再补一次**。
- `on_hotkey()` 去掉原来不够稳的 `sleep(0.25)`；并新增**取证日志**：
  按下瞬间若修饰键仍按着，日志会写明（下次一按就能看到证据）。
- ⚠️ 只用通用键码 0x10/0x11/0x12（GetAsyncKeyState 对左右分键码 0xA0~0xA5 不灵）。

**配合**：钩子版（上一节）负责"吞掉 B"，本次修复负责"复制别变成 Ctrl+Alt+C"，**两条一起才彻底**。
必须先重启桥（当前跑的还是旧版：日志是 `全局热键已注册`，新版会写 `钩子抢键模式`）。

## 11:35 新增：发送结果视觉回执（光标提示条 + 托盘闪烁）

**需求**（木木原话）："加入一个新的功能，截图成果后，托盘上的那个图标要闪烁，

**拷问结论**：先核实平台能力——**Windows 没有"闪烁托盘图标"的系统 API**，
只能 `SetTimer` + 反复 `NIM_MODIFY` 切换图标来伪造（社区通行做法，已验证）。
又发现"4 秒"这个数字有歧义：**发送本身实测就是 4.0 秒**，
所以"闪 4 秒"既可能是"成功后闪 4 秒"，也可能是"按下就闪、发送完即停"——必须问清。

**定稿（三轮拷问全部闭合）**：
| 分支 | 定稿 |
|---|---|
| 反馈方式 | 光标旁小提示条 **+** 托盘图标闪烁（双保险）——我建议的"光标提示"被采纳 |
| 触发时刻 | 结果出来后才提示（不提示"发送中"） |

| 图标样式 | 正常 ↔ **✓ 绿勾**交替；失败用 **✗ 红** |
| 闪烁时长 | 成功 2.5 秒（间隔 0.5s）；失败 4 秒 |
| 成功气泡 | **关掉**（原气泡会显示消息内容预览，与"不显示内容"矛盾） |
| 失败气泡 | 保留红气泡 |
| 菜单 | 新增「预览提示效果」 |
