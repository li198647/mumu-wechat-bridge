# mumu-wechat-bridge · 微信桥

把**选中的文字**（或剪贴板内容）一键发到电脑版微信的**「文件传输助手」**的小工具。

在任何程序里选中一段文字 → 按 `Ctrl+Alt+B` → 一秒钟后打开手机微信，文字已经在「文件传输助手」里了。

- 不发好友、不发群，**只发给自己**，所以不存在发错人的风险
- 不碰微信客户端本身，走的是**微信官方网页版**
- 发送后**回读页面校验**，消息真的出现了才算成功，**绝不假报成功**
- 结果通过**光标旁的小提示条 + 托盘图标闪烁**双通道反馈

---

## 一、为什么不是"直接驱动电脑版微信"

这是本项目最开始想走的路（社区里 wxauto / WeChatFerry 那一类工具就是这么干的），
但在本机**实测判死**。把这个结论放在最前面，是为了让别人不用再踩一遍。

测试环境：微信 **4.1.15.13**（`C:\Program Files\Tencent\Weixin\Weixin.exe`），
Windows 10，DPI=96、单显示器（这两个是社区常提的"UIA 读不出来"的诱因，这里都已排除）。

用两个独立探针（`tools/probe_deep.py`、`tools/probe_msaa.py` / `probe_msaa2.py`）
从**四个入口**去读微信的界面控件，结果**全部空手**：

| 入口 | 结果 |
|---|---|
| UIA RawViewWalker | 只走到 Pane `MMUIRenderSubWindowHW`，再往下 `COMError(-2147467261 无效指针)` 断掉 |
| UIA ControlViewWalker | 与上面逐字相同，同一个点断掉 |
| UIA FindAll（Edit / ListItem / Button / Text / Document） | **全部 0 个**（顶层窗口与渲染子窗口都是 0） |
| 焦点元素 `GetFocusedElement`（光标就点在微信输入框里） | 焦点仍报成顶层窗口 `微信 / Qt51514QWindowIcon` |
| MSAA 子节点（oleacc / IAccessible） | `OBJID_CLIENT` 只有 1 个子节点；`OBJID_WINDOW` 有 7 个但名字和角色全读不出 |
| MSAA 坐标网格（窗口内 247 个点逐个 `AccessibleObjectFromPoint`） | 只认出 2 种对象：`CLIENT=MMUIRenderSubWindowHW`、`WINDOW=微信` |

结论：**微信 4.x 的界面是一张自绘画布**，它既没有向 UIA 暴露元素，也没有向 MSAA 暴露元素。
主窗口类名是 `Qt51514QWindowIcon`——**不是**社区文档里写的 `mmui::MainWindow`。
所以"读控件树"这条路在本机走不通，与登录状态无关（复测过两遍，结论更硬）。

顺带排除了另外几条路：

| 路线 | 为什么不用 |
|---|---|
| Hook 注入微信进程（WeChatFerry 类） | 作者本人明确不接受（"不喜欢偷偷摸摸的感觉"） |
| 公众号测试号模板消息 | 落点错了（那是发给公众号、不是文件传输助手），且模板字段限长、一天几条就被限流 |
| 盲操作 / OCR 键盘流 | 会抢焦点，可能把消息发错会话 |
| 改 Qt 渲染后端（`QT_OPENGL=software`） | 社区有人成功过，保留作为日后翻案的实验 |

**最终选的是微信官方网页版** `szfilehelper.weixin.qq.com`（`filehelper.weixin.qq.com` 会跳到这里），
用 Playwright 操作。不注入、不 hook、不改客户端，走的是官方通道。

## 二、架构

```
你按 Ctrl+Alt+B
      │
      ▼
wx_tray.py 的 WH_KEYBOARD_LL 低级键盘钩子（抢在别的程序之前拿到按键，并吞掉它）
      │
      ▼
wx_bridge.py 取文字：先等 Ctrl/Alt 松开 → 给前台程序注入 Ctrl+C → 读剪贴板
      │                                  （抓不到就退回剪贴板原有内容）
      ▼
wx_send.py → Playwright connect_over_cdp → 常驻 Chromium（9222 端口）
      │          找到页面 → 填入 textarea → 点 a.chat-send__button → 回读校验
      ▼
微信「文件传输助手」
      │
      ▼
wx_toast.py（光标旁提示条）+ wx_tray.py（托盘图标闪烁）
```

两个关键设计：

**1. 浏览器必须独立常驻，桥脚本随时可以重启。**
微信网页版的登录会话与「浏览器进程是否活着」强绑定——浏览器一关，服务端立刻注销 session
（实测过：把 cookie 快照原样注入回去也救不回来，这不是 profile 落盘问题，是服务端行为）。
所以桥自己拉起一个带 `--remote-debugging-port=9222` 的 Chromium，脚本用 `connect_over_cdp` 连上去干活。
好处是**改代码、重启桥都不影响登录态**，不用反复扫码。

**2. 必须由你自己双击启动。**
实测发现：由其他程序（自动化工具、父进程）启动的浏览器会被**连带清理**，
连 `DETACHED_PROCESS`、`CREATE_NEW_PROCESS_GROUP`、`CREATE_BREAKAWAY_FROM_JOB` 都救不了。
所以入口是一个 `.bat`，请你双击。

## 三、安装

需要 Python 3.10+ 和两个包：

```bash
pip install playwright pillow
python -m playwright install chromium
```

然后把整个文件夹放到任意位置（**路径不要改来改去**，登录态的 profile 是跟着目录走的）。

## 四、使用

1. **双击 `启动微信桥.bat`**。
   - 第一次会跳出浏览器窗口，用手机微信「扫一扫」扫二维码（二维码过期会自动换新）。
   - 登录成功后窗口缩进系统托盘，可以看到一个绿色对话气泡图标。
2. 在任意程序里**选中一段文字**，按 `Ctrl+Alt+B`。
3. 光标旁边会弹一个小提示条，托盘图标同时闪一下——看到就说明发出去了。

没选中文字也能用：直接按热键，它会发**剪贴板里的内容**。

**托盘图标右键菜单**

| 菜单项 | 作用 |
|---|---|
| 发送剪贴板 | 等价于按热键，但只发剪贴板、不抓选中文字 |
| 预览提示效果 | 只弹提示条 + 闪图标，**不会真的发消息**——用来先看观感 |
| 热键检测 | 逐个试注册，列出本机哪些组合可用 |
| 显示日志 | 打开 `tools/wx_bridge.log` |
| 重启微信桥 | 改完代码后重载（**登录态不受影响**） |
| 退出微信桥 | 正常退出（⚠️ 别去任务管理器杀 chrome） |

## 六、已知限制

1. **登录态会掉。** 网页版的 session 长期闲置会被服务端注销（实测 3 天内可掉）。
   掉了就要重新扫码，这是微信服务端行为，绕不过去。
2. **没有开机自启。** 每次开机要手动双击一次 `启动微信桥.bat`。
3. **浏览器死掉 = 登录态失效。** 目前没有守护进程盯着它。
4. **只发文字。** 不支持图片、文件、表情。
5. **只发「文件传输助手」。** 这是刻意设计的：不会发错人。

## 七、踩过的坑（挑几个值得记的）

- **取选中文字时，注入 `Ctrl+C` 之前必须等修饰键松开。**
  热键触发的瞬间手指还按着 `Ctrl`/`Alt`，此时注入 `Ctrl+C`，系统收到的是 `Ctrl+Alt+C`
  ——复制失败（只能退回旧剪贴板），还会误触发别的软件的功能。
  修法：注入前轮询 `GetAsyncKeyState` 等四个修饰键松开，超时则强制注入 KEYUP。
- **多行文字不能用键盘逐字敲。** 敲到换行会直接发出去，消息被切碎。
  要用整体填充（`fill()`），这样三行文字能作为**一条**消息发出，换行完整保留。
- **点发送按钮必须点真正的 `a.chat-send__button`。** 点它外层的容器 `div` 无效（不发消息），
  这个坑当时排查了很久。
- **`RegisterHotKey` 试注册成功 ≠ 这个组合真的没人抢。**
  用低级键盘钩子或 RawInput 抢键的程序（QQ 的截图就是）**测不出来**。
  所以本桥改用 `WH_KEYBOARD_LL` 自己吞键，抢在它们前面。
- **Windows 没有"让托盘图标闪烁"的 API。** `Shell_NotifyIcon` 只有 ADD/MODIFY/DELETE。
  只能用 `SetTimer` + 反复 `NIM_MODIFY` 在两个图标之间切换来伪造。
  定时器还必须装在**有消息循环的线程**上，否则收不到 `WM_TIMER`。
- **`ctypes` 的三个坑**：`DrawTextW` 在 `user32` 不在 `gdi32`；
  `GetDC` / `GetModuleHandleW` 不声明 `restype` 会被默认 `c_int` 截断 64 位句柄（直接崩）；
  别用空 `except` 静默吞异常——会让人排查到怀疑人生。
